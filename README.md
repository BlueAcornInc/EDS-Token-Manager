# Trailhead (AramarkTrailhead)

Adobe App Builder tool for **Parks & Destinations** brand sites on Edge Delivery Services (EDS).

Admins can:

1. **Create a trail/site** — scaffold GitHub files + open a PR (`create-site`)
2. **Edit brand tokens** — colors, greys, logo with live preview (`manage-tokens`)
3. **Request release** — publish `brands/{slug}/tokens.css` via PR to staging (`publish-tokens`)
4. **Inspect content status** — Helix preview/live vs AEM (`content-status`)

> **Porting tier: `to-staging`** — based on `to-main`, plus the modular style-guide
> preview (including expanded read-only EDS reference tabs) and the RBAC enablement
> runbook.
>
> **EDS CDN:** `https://staging--{siteCode}--{org}.aem.live`. `org` comes from
> `GITHUB_OWNER` (e.g. `aramark-destinations`) — never the GitHub repo name.
> `siteCode` comes from brand meta / `site.json` (shown as a Basecamp column;
> editable via Edit site info). New sites get a short slug from create-site;
> legacy Helix full-folder names should already be stored in meta. If unset,
> CDN falls back to the brand folder slug.
>
> Keep `AUTHZ_ENFORCE=false` until Admin Console Product Profiles exist — then follow
> `documents/RBAC-ENABLEMENT.md`.

## Stack

| Layer | Tech |
|-------|------|
| Runtime | Adobe I/O Runtime (Node.js 22 actions) |
| State | `@adobe/aio-lib-state` (KV; ~365-day TTL) |
| Auth | Adobe IMS (`require-adobe-auth`) + optional Product Profile RBAC (`AUTHZ_ENFORCE`) |
| GitHub | GitHub App installation token (not a PAT) |
| UI | Vanilla JS SPA in Experience Cloud Shell (`web-src/`) |

Package name in Runtime: **`AramarkTrailhead`**.

Git operations against the EDS repo (`create-site`, `publish-tokens`, `list-sites`,
`manage-tokens` inventory, `remove-brand`, `content-status`) all default to the
**`staging`** branch — see `actions/branches.js`.

## Quick start

```bash
npm install
aio login
aio app use          # writes .env (never commit it)
# Add GitHub App + owner/repo vars to .env — see below
aio app run          # UI at localhost:9080; actions on Runtime
```

```bash
npm test             # unit tests
npm run lint
```

## Environment (`.env`)

Generated by `aio app use`, then add:

```bash
# GitHub App (server-side only)
GITHUB_APP_ID=
GITHUB_APP_PRIVATE_KEY=
GITHUB_APP_INSTALLATION_ID=
GITHUB_OWNER=
GITHUB_REPO=

# Optional
AEM_BEARER_TOKEN=          # Content Explorer AEM tree
AUTHZ_ENFORCE=false        # set true to enforce Product Profile RBAC
```

### Turning on RBAC

`AUTHZ_ENFORCE` is **off by default**. Enabling it requires Adobe Admin Console
Product Profiles **and** a redeploy — it will not restrict anyone until both are
done.

**Runbook:** [`documents/RBAC-ENABLEMENT.md`](documents/RBAC-ENABLEMENT.md)

## Actions

| Action | Purpose |
|--------|---------|
| `manage-tokens` | Brand token CRUD + meta/rename/repair |
| `publish-tokens` | Draft tokens → CSS → GitHub PR (staging) |
| `list-sites` | List `brands/` from GitHub |
| `create-site` | Scaffold new brand site + seed state |
| `remove-brand` | Clear brand state (+ legacy index.json if present) |
| `content-status` | Preview / live / AEM status for a path |

Optional RBAC groups (when `AUTHZ_ENFORCE=true`) are defined in `actions/authz.js`.
How to enable: [`documents/RBAC-ENABLEMENT.md`](documents/RBAC-ENABLEMENT.md).
Background: `documents/ENHANCEMENT_APPROACH.md`.

## State key contract

| Key | Meaning |
|-----|---------|
| `brand.__index__` | JSON array of brand slugs |
| `brand.{slug}` | Draft token JSON |
| `brand.{slug}.status` | `drafted` \| `pending` \| `synced` |
| `brand.{slug}.meta` | `{ fullName, domain, ... }` |
| `brand.{slug}.pr` | Open create-site PR ref |
| `brand.{slug}.audit` | `{ lastSavedBy, lastSavedAt, lastPublishedBy, lastPr, ... }` |
| `branch.seq.{slug}` | Branch name counter |

## Release branches and previews

`create-site` and `publish-tokens` create working branches named
`TB-{brand-slug}-{sequence}` (for example, `TB-ONP-1`). Including the full slug
prevents different brands with the same initials from colliding.

Release branch previews use
`https://{branch}--{site-code}--{github-owner}.aem.page/`. The site code comes from
`brand.{slug}.meta.siteCode`, falling back to the brand slug; the owner is `GITHUB_OWNER`.
The branch name is lowercased in the hostname (for example,
`TB-ONP-1` becomes `tb-onp-1`). The release PR still targets `staging` and does not
publish changes until merged.
